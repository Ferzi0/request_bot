## Решения заказчика (2026-10-17)

- Заказчик хорошо знает Python и aiogram, хочет глубже изучить; код должен быть образцовым и читаемым (архитектура, комментарии по делу), чтобы по нему можно было учиться.

- Заявка: человек проходит диалог → бот отправляет **заявку заказчику в личный чат с ботом** (ADMIN_ID) сообщением с данными, указанными клиентом. Клиенту: «Принято, отвечу в течение суток».

- Тон: формально, по-человечески, на «вы», только русский.
- Название кнопки/действия: «Оставить заявку». Имя и username бота — решит заказчик (создаёт в @BotFather).
- Токен бота и ID заказчика — ТОЛЬКО в `.env` (в git не попадает), заказчик вставляет сам, в чат токен не присылать.
- Коммиты — только от имени заказчика (его git-конфиг), без строк атрибуции (Co-Authored-By и подобных).
- Окружение: Python 3.14.8 на Mac (aiogram совместимость проверить; при проблемах — Python 3.12/3.13 в venv без системных изменений).

### Что сделано
- Бот на aiogram 3.31.0, long polling, `python -m bot`. Диалог повторяет форму сайта (`#brief-form`): имя (2–80) → почта/Telegram (≤ 120; почта, `@ник`, `t.me/ник`; ник и ссылка приводятся к `@ник`) → тип проекта (6 кнопок, подписи как на сайте) → задача (10–1000, только текст) → согласие («Согласен»/«Отмена»; со ссылкой, если задан `POLICY_URL`, иначе текст без ссылки) → сводка «Отправить / Изменить / Отмена». «Изменить» — выбор поля (имя, контакт, тип, задача), после ввода сразу снова сводка. Кнопки «Использовать имя из Telegram» (показывается, только если имя проходит проверку) и «Ответить мне в Telegram» (нет ника → всплывающее сообщение, человек остаётся на шаге). `/start site` → источник «сайт», иначе «бот»; источник переживает отмену. `/start`, `/help`, `/cancel` и «Отмена» — на любом шаге; старые кнопки прошлых шагов отвечают «Эта кнопка уже неактуальна» и снимаются.
- Клиенту после отправки: «Заявка принята. Отвечу в течение суток.» + номер заявки. Приветствие — только факты из `../ferz-site/STATUS.md` (имя, Ferz, Челябинск, виды работ, удалённо, ответ в течение суток).
- Администратору (`ADMIN_ID`): номер (`ГГММДД-XXXX`, случайный хвост, без БД), дата/время в `TIMEZONE`, источник, имя, контакт, тип, задача, Telegram-данные (id, @ник, имя-упоминание `tg://user?id=`). Всё пользовательское — через `html.escape` в одном модуле `services/formatting.py`. Кнопки: «Написать клиенту» (ник из профиля → ник из контакта → `tg://user?id=`) и «✅ В работу» (проверка `from_user.id == ADMIN_ID`; дописывает отметку со временем, убирает свою кнопку, ссылку оставляет). Если Telegram отклоняет кнопку `tg://user` (`BUTTON_USER_PRIVACY_RESTRICTED`), заявка уходит без неё.
- Повторы отправки администратору: сеть/5xx — 3 попытки с паузами `SEND_RETRY_DELAYS` (1 с, 3 с), RetryAfter — ждём сколько сказал Telegram (не больше 30 с); 400/403 — без повторов. Не доставлено → клиенту честное сообщение с `FALLBACK_CONTACT`, сводка с «Отправить» остаётся для повтора; в лог — номер заявки и класс ошибки, без данных.
- Защита: санитайзер (Cc/Cf/Co/Cs/Cn, в т.ч. zero-width и bidi U+202E, схлопывание пробелов, NFC), лимиты длин с сообщением «N символов при лимите M» (без молчаливой обрезки), только личные чаты (outer-middleware на message и callback_query — в группах бот молчит), двойная отправка (синхронный `InFlightGuard` до первого `await` + сброс состояния после успеха), антифлуд — `APPLICATIONS_PER_HOUR` (3) доставленных заявок в час на user id, скользящее окно в памяти; сбой доставки лимит не расходует.
- Логи: `logging`, уровень `LOG_LEVEL`; пишутся только id, длины, этапы; `RedactingFormatter` вырезает токен из любой строки лога, включая трейсбеки. Глобальный errors-хендлер: клиенту нейтральное «Что-то пошло не так…», в лог — тип и трейсбек. Остановка по Ctrl+C/SIGTERM штатная (`start_polling` + закрытие сессии в `finally`).
- Старт: токен проверяется `getMe` до polling (Unauthorized/нет сети → понятное сообщение, код 1); `deleteWebhook(drop_pending_updates=False)` — заявки, пришедшие при выключенном боте, не теряются; меню команд; пробное сообщение администратору «Бот запущен…» (`NOTIFY_ADMIN_ON_START`), при неудаче — подсказка в логе «откройте бота и нажмите /start».
- Хранилище: протокол `ApplicationRepository` + `NullRepository` (ничего не хранит). SQLite добавится новым классом и одной строкой в `bot/app.py`, хендлеры не меняются.

### Решения
- **Python 3.14.8 системный — подошёл.** aiogram 3.31.0 официально поддерживает 3.10–3.14 (classifiers на PyPI), pydantic 2.13.5 / pydantic-core 2.46.5 ставятся колёсами под 3.14. Отдельный Python не понадобился. venv: `.venv` в проекте (в `.gitignore`), создан `uv sync --python $(which python3)`; глобально ничего не ставилось.
- **pyproject.toml + uv.lock** (uv 0.12.23 уже стоит у заказчика): зависимости и dev-группа в одном месте, lock с точными версиями и хешами. Для тех, кто без uv, — `requirements.txt`, сгенерированный `uv export` (команда в README).
- Dev: pytest 9.1.1, pytest-asyncio 1.4.0, ruff 0.17.1, mypy (strict + плагин pydantic).
- Часовой пояс: в задании — `Europe/Yekaterinburg`, но такого IANA-имени нет; верное — **`Asia/Yekaterinburg`** (UTC+5, Челябинск). Неизвестный пояс в `.env` → понятная ошибка.
- Минимумы длины взяты с сайта (`js/main.js`): имя от 2, задача от 10 символов — чтобы правила бота и формы совпадали.
- Роутеры — фабрики, а не глобальные объекты: aiogram не даёт подключить роутер к двум диспетчерам, а тестам нужен свежий на каждый тест. Регистрация хендлеров собрана в конце модуля — видно «карту» шагов и порядок.
- HTML parse_mode: экранирование стандартным `html.escape`; Markdown V2 требует экранировать 18 символов.
- `FALLBACK_CONTACT` в `.env.example` — публичные контакты с сайта (почта и @ferzV1 из `index.html`). `POLICY_URL` пустой, пока нет домена.
- Номер заявки — дата + 4 hex: без БД счётчик обнулялся бы при перезапуске.

## Антибаг: этап 1 (Opus)

**Статус:** проверено, дефекты исправлены — готово к монитору. Коммит не делался. Реального Telegram не было (токена нет).

### Найдено
**Критично** — нет. Токен и ADMIN_ID не утекают (repr/dump/ошибки настроек/лог с DEBUG — 0 вхождений), HTML экранируется везде, «В работу» только у ADMIN_ID, группы игнорируются.

**Важно**
1. **Гонки апдейтов одного пользователя.** aiogram обрабатывает апдейты параллельно, замка на пользователя не было. Воспроизведено: имя и почта, отправленные подряд, → обе записались как имя, вопрос «Шаг 2» пришёл дважды; двойное нажатие типа проекта → «Шаг 4» дважды; двойное «Согласен» → две сводки. Исправлено: `Dispatcher(events_isolation=SimpleEventIsolation())` — апдейты одного пользователя идут строго по очереди (`bot/app.py`). `InFlightGuard` после этого никогда не срабатывал бы (тот же ключ) — удалён вместе с текстом `ALREADY_SENDING`; двойная «Отправить» → одна доставка, второе нажатие получает «Эта кнопка уже неактуальна».
2. **Команды `/foo` сохранялись как ответ** (долг исполнителя). Исправлено: любая команда, кроме /start, /help, /cancel, на любом шаге → «Такой команды нет. Доступны /start, /help и /cancel. Если это ответ на вопрос, напишите его без «/» в начале.» (новый текст `UNKNOWN_COMMAND`), шаг не меняется. «/ текст» (с пробелом) командой не считается, как и у Telegram.
3. **Дубли после повтора неразличимы** (долг исполнителя). Простой идемпотентный путь: номер заявки выдаётся один раз на черновик (`ApplicationDraft.app_id`) и сохраняется при повторе «Отправить» после сбоя. Дубль из-за таймаута после фактической доставки (и при авто-повторах, и при ручном) приходит администратору **с тем же номером** — сразу виден. Полностью исключить дубль нельзя: у sendMessage нет ключа идемпотентности.
4. **Пользователь заблокировал бота → ERROR с трейсбеком** в логе на каждый его апдейт. Исправлено: `TelegramForbiddenError` в errors-хендлере → INFO «Пользователь заблокировал бота», без трейсбека.
5. **Ошибка запуска с трейсбеком в обход фильтра токена:** `deleteWebhook` стоял вне try — при обрыве сети между getMe и deleteWebhook (и при 5xx/RetryAfter на getMe) исключение уходило в `sys.excepthook` (мимо `RedactingFormatter`). Исправлено: оба вызова в try, плюс общий `TelegramAPIError` → понятное сообщение, код 1.

**Мелочь**
6. **Грамматика чисел:** «81 символов при лимите 80», «не меньше 2 символов», «1001 символов». Добавлена `texts.chars(n)` (1 символ / 2 символа / 5 символов); тексты `NAME_SHORT`, `TASK_SHORT`, `TOO_LONG`, `ASK_TASK` теперь подставляют число со словом. Смысл текстов не менялся.
7. **Повторное «В работу»** (двойной тап или старый экран) дописывало вторую отметку, а в ту же минуту падало «message is not modified» → администратору «Что-то пошло не так». Исправлено: если в присланном Telegram сообщении уже нет кнопки «В работу» — только всплывашка «Отмечено: в работе.».
8. **Подделка строк лога:** при отказе в доступе `app_id` из callback_data постороннего писался в лог как есть (перевод строки → фальшивая строка лога). Теперь `%r`.
